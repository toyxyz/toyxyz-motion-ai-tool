**Join existing motion (0.44.2).** Select the block or contiguous blocks to generate. The first block uses the existing start continuity, and the last block targets the start of an immediately following generated clip. Kimodo uses **Transition Overlap** from the following Kimodo block, or from the selected Kimodo block when the following clip uses another model. ARDY and MotionBricks use up to four 30 FPS samples. The generated result applies to the selected blocks only. Restart Blender and the companion app after updating.

**Version 0.40.0 — native SOMA bones:** removed the added FK/IK control rig, poles, widgets and synchronization. Actors use their original 77 SOMA bones and preview mesh. Native keys, motion timelines and NLA corrections remain. Old controller animation is not converted. Restart Blender. [Details](../../docs/CONTROL_RIG_REMOVAL.md).

**Generation startup (0.36.2):** Generate Motion starts the companion if stopped, connects and submits once after the health/lifetime handshake. Temporary connection refusal during startup shows a waiting message. Restart Blender after updating.

**Actor names (0.36.1):** new rigs use `actor_01`, `actor_02`, etc.; matching bodies use `actor_01_mesh`. Existing tool-default names migrate once after restarting Blender. Custom rig names and later manual renaming remain supported.

**Capture Pose removed (0.36.0):** the image capture button, window, apply operators and companion image routes were removed at the user's request. Existing native body keys and generated NLA remain editable. Restart Blender and the companion after updating. See [removal details](../../docs/CAPTURE_POSE_REMOVAL.md).

**Automatic shutdown (0.35.0):** closing or crashing the last owning Blender terminates the companion and its model processes. Shared companion use retains the app until the last Blender exits. Restart Blender after updating, then click Start once. See [implementation and verification](../../docs/BLENDER_APP_LIFETIME.md).

**Clear Motion**, below Generate Motion, removes generated results for selected blocks while keeping their native user pose keys, block settings and prompts. It supports multiple selections, native Undo/Redo and saved scenes. See [clearing generated motion](../../docs/CLEAR_MOTION.md).

The top app control switches from **Start** to **Stop** while the companion is running and returns to **Start** after shutdown. The small **chain icon** beside it reconnects without launching another process. The separate bottom Stop App button has been removed; **Release GPU** remains available. Restart Blender to load the updated controls.

Version **0.33.0** adds **SOMA Rigs**: click **Add SOMA Rig** for another character, then select a rig in the list to edit its independent blocks, prompts, pose keys, generation settings and NLA motion. Pending generation stays bound to its original rig when selection changes. Existing single-rig scenes migrate automatically. Restart Blender; the companion needs no restart. See [multiple rig workflow](../../docs/MULTIPLE_SOMA_RIGS.md).

Version **0.32.0** adds **Show Pose Targets**: selected motion blocks display their actual input constraints directly in the 3D viewport. Full Body targets use blue skeletons; hands, feet and root goals use distinct colored spheres. No scene objects or animation keys are added. Display options are in Advanced. Restart Blender; the companion needs no restart. See [pose target preview](../../docs/POSE_TARGET_PREVIEW.md).

Version **0.31.0** removes the block Modifiers menu and experimental Foot Contact feature at the user's request. Generated NLA clips, manual pose keys and scene objects are preserved. Old modifier route assignments become ordinary block Path Curves; Curve Start (%) and manual foot constraints remain supported. Restart Blender and the companion after updating. See `docs/FOOT_CONTACT.md` in the companion repository for removal and compatibility details.

Curve Start (%) controls when a block starts following its route: 0 is the beginning, 50 is halfway, and 100 targets the curve start at the final sample. It scales with block duration. Constraint types are edited by right-clicking native pose diamonds; the dynamic sidebar selector was removed in v0.28.1. SOMA rig creation also includes an optional skinned preview mesh.

Version **0.25.0** adds direct editing of the timeline's native **Keyframes** row. Select pose diamonds with click/Shift-click or a box, drag or use G to move them, and use X/Delete to remove them. Compound constraints move/delete with the real keys. The last active row determines keyboard editing; Key and Block menus provide explicit commands. Generated NLA and selected motion-block timing are preserved. Restart Blender after updating. See `docs/TIMELINE_POSE_EDITING.md` in the companion repository.

Version **0.24.1** removes the experimental Smart Primitive UI, editor and route generation. Offline motion blocks, native pose constraints and NLA correction layers remain supported. Existing boxes, stored poses, draft rigs and generated NLA animation are retained; compatibility recovery restores a main rig hidden by an old edit session. Restart Blender after updating. See `docs/SMART_PRIMITIVES.md` in the companion repository for removal and compatibility details.

Version **0.23.0** adds multi-select **Constraint Types**. At a native keyed frame, toggle several hand/foot/root goals in the sidebar, or right-click the key diamond and confirm several goals in its dialog. Timeline labels show **LH+RH**, **LH+RF**, etc. Full Body is exclusive; clearing the last partial goal restores FB. Kimodo and ARDY support these combinations; MotionBricks requires Full Body. Existing single-type annotations and user keys remain compatible. Restart Blender after updating; no companion restart is required. See `docs/KEYFRAME_CONSTRAINT_TYPES.md` in the companion repository.

Version **0.22.1** fixes one-frame FK pops when applying partial constraint results. Full Body retains authored local-channel priority; hand/foot/root targets retain the generated solution without a single-frame restoration of old FK keys. Source keys remain intact. Restart Blender and regenerate affected clips. See `docs/PARTIAL_CONSTRAINT_FK_POP_FIX.md` in the companion repository.

Native pose keys have a **Constraint Type** in v0.22.0. Scrub to a keyed frame and edit it in the sidebar, or right-click its diamond in the dedicated timeline. Small **FB/LH/RH/LF/RF/R2** labels indicate Full Body, hands, feet or root 2D. Kimodo/ARDY use the selected type; MotionBricks requires FB. Types are Action-slot metadata that follow native key moves/deletion and persist through save/reopen and Undo/Redo. See `docs/KEYFRAME_CONSTRAINT_TYPES.md` in the companion repository.

**ARDY** is available as a block model in v0.21.0. It generates exactly the block duration through bounded autoregressive windows, with prompts, ordinary pose keys, shared Path Curves, previous-clip history and BF16/INT8/NF4 encoder options. The minimum is one 30 Hz output frame; ARDY has no model-imposed duration maximum and ARDY-only selections have no 60-second operation cap. Its 60-frame horizon and four-frame tokens are internal processing sizes. Advanced exposes separate ARDY denoising steps (1–10). Results apply to the same native NLA track and SOMA rig. See `docs/ARDY_BLOCKS.md` in the companion repository.

Kimodo blocks expose **Transition Overlap (30 FPS)** in the sidebar and double-click popup. In v0.20.0, the first or only selected block also uses the actual tail of an adjacent existing generated clip, including user corrections. Default 5 controls the incoming transition; values use 30 FPS model frames and cannot exceed the previous clip/block length. Existing predecessor Actions and source keys remain untouched, and only selected intervals are applied. No adjacent generated result means no history overlap. MotionBricks generation retains its fixed four-pose context. See `docs/KIMODO_TRANSITION_OVERLAP.md` in the companion repository.

Kimodo blocks support an optional **Path Curve** in the sidebar and double-click popup. In v0.18.1, touching enabled blocks with the same Curve object share one horizontal traversal over their combined duration. Regenerating only some group blocks retains their assigned sections; unselected neighbors are not regenerated. Gaps, different Curve objects, a missing curve or a different model end the group. A single block uses the whole curve. Scene placement and scale are respected; posture/height come from generation or native pose keys. Leave it empty for normal generation. Different adjacent curves need meeting endpoints, and a curve section following previous motion should start at that motion's endpoint. The standard postprocessor allows about 4 cm of hip sway around the route. Curves are sampled at the group's start for generation, not followed live after editing; regenerate to update. MotionBricks continues to use pose targets. See `docs/KIMODO_PATH_CURVES.md` in the companion repository.

Enable this folder as a Blender 5.2 add-on. Leave **External App Folder** blank for automatic detection or set it to the companion root to choose a specific installation. AI runs outside Blender using the app's embedded Python.

**Generate Motion** automatically connects to a running companion app before submitting if needed. Connection is asynchronous and generation continues once connected, using the originally selected blocks. Cancel stops a pending generation. If the connection times out, start the app and generate again; no request is silently submitted after timeout.

Version **0.17.0** shows a native percentage progress bar during generation. Kimodo uses completed denoising steps and MotionBricks uses completed transitions. Model loading shows its stage at 0%; fast single-call MotionBricks jobs can finish before an intermediate percentage is visible. Mixed-model progress continues across runs and reaches 100% after the final automatic Blender application. Block names are automatic: the sidebar and prompt/notes popup no longer expose a name field, and persistent IDs still manage NLA links.

Version **0.16.2** corrects MotionBricks' local joint-frame conversion. Canonical SOMA rotations are converted to the official model's native bone frames for context/targets and converted back on output. Earlier endpoint tests did not catch the resulting intermediate-motion error. Regenerate affected blocks after updating/restarting the companion runtime; existing clips are not rewritten automatically. See `docs/MOTIONBRICKS_JOINT_FRAME_FIX.md` for evidence and remaining timing/pose limitations.

The sidebar has a single **Start** button: it launches and connects to a stopped app, or connects directly if the app is already running. There is no separate Connect button.

The companion keeps the current motion model resident between jobs. **GPU Model** shows the engine held in memory. Repeated jobs reuse it, generating with another engine replaces it, and **Release GPU** unloads the motion model plus the portable app's shared text encoders. The next job reloads what it needs. Cancelled/failed workers restart cleanly. Restart the app after this runtime update.

In the 3D View **Motion AI** sidebar, click **Start**, **Create SOMA Rig**, then **Open Motion Timeline**. Use **Add Block** in the dedicated timeline header, click/Shift-click to select, or drag empty graph space to box-select. The selection rectangle uses a gray/white dashed border and subtle neutral fill. Shift-box adds, Ctrl-box subtracts, B starts box selection, A selects all and Alt+A deselects. Drag a selected group to move it, drag an edge to resize, and double-click to edit the active block's prompt. X/Delete removes selected blocks and their linked clips. The sidebar has no duplicate management list or Add/Delete row; it keeps the active block's settings, including Enabled. The frame ruler scrubs the playhead. Model limits constrain resizing. Advanced parameters are collapsed in the sidebar; the header reuses Blender's native Timeline controls.

**Generate Motion** is the only generation command. One selected block generates alone; multiple selected blocks generate in chronological order. Touching enabled blocks can use either model, without gaps or overlaps. Same-model runs share one sequence request. At each model change the preceding run is applied first, then its composed endpoint starts the next run. Cancel/failure stops pending runs, and changing sequence block settings stops further submission. Unselected neighbors are never added automatically. Kimodo uses ordered text prompts and transition context. MotionBricks uses native pose keys and carries four generated context poses between transitions; its Notes field is not a text prompt. Pose keys can be anywhere inside the selected range, without keys at block boundaries. The final keyed pose is the stop target at its authored time; remaining block time holds that pose. Without previous motion, at least two pose keys are needed; with previous motion, one destination key is sufficient. Keys closer than one 30 FPS model sample are rejected with their frame numbers.

All three models share a single motion-block row; model names stay in the block labels. A row underneath mirrors the input SOMA Action's real pose keys using Blender's native key colors. Edit/delete these keys with Blender's native animation tools; the display updates automatically and does not create pose records. Generated NLA keys are excluded. The sidebar has no block length or Start/End controls: move and resize blocks in the timeline, with model duration limits applied automatically. New blocks append after the shared last block and snapping works across models.

Insert/edit ordinary SOMA pose-bone keys directly over generated playback. The active user Action is a native **Combine** correction layer above the generated NLA base. Both layers play together at every frame, without mode or Solo switching. Native key commands and Auto Key record the user's edit relative to the visible base; corrections interpolate normally between keys. Only user keys appear in the native Timeline. Generation reads the composed poses and avoids applying their correction twice to new results. Existing absolute keys convert once with an **Absolute Keys Backup** Action. Navigation follows Blender Timeline defaults, including MMB pan, wheel zoom, Ctrl+MMB zoom, Home and Numpad period. The ruler, current-frame tag, background, font and scrollbar follow the live Blender theme. **View > Match Blender Timeline** copies a visible native Timeline's start/zoom for comparison.

Completed generation applies automatically on a native NLA playback track on the same SOMA armature. Live strips are ordered on that track with Extrapolation set to **Hold**. Obsolete plain, muted tool playback tracks are removed after success so disabled generation rows do not accumulate. Existing saved history rows are also cleaned on initialization. User/mixed/locked/customized tracks are preserved, and Actions are not globally purged. No Apply Result click is required. The user's active Action/slot and correction keys are retained. Both layers use native Blender evaluation and remain composed when the addon is disabled. Insert neutral correction keys around a localized edit to limit its duration; ordinary curve interpolation and extrapolation apply.

Motion blocks and generated NLA strips share persistent IDs. Moving/resizing a block updates all its native result versions; deleting it removes matching strips. Native NLA edits also update the block. Deleting a current playback strip removes its block and matching history. Undo/redo and save/reopen preserve links. User pose keys stay independent. A block moved during generation receives its result at the new timing; deleted or model/prompt-changed blocks are skipped. Application waits through Edit/Tweak Mode or an FPS mismatch. An unkeyed new start inherits the preceding result's ending pose, including root position. Explicit start keys take priority. MotionBricks also inherits four recent poses. No inherited keys are baked into the user Action. Playback uses no Python pose handler or influence driver.
