# Kimodo and ARDY Path Curves (v0.29.0)

Select a Kimodo or ARDY block in the Motion Timeline and choose **Path Curve** in the sidebar. The same searchable selector is in **Edit Motion Block** (double-click a block). Use a regular Blender Bezier, Poly or NURBS Curve containing one continuous spline. Enter a motion prompt such as `A person walks forward along a curved path.` and click **Generate Motion**. Clear Path Curve to generate as before. MotionBricks remains pose-to-pose generation and does not expose this constraint.

## Curve Start (%)

After assigning a curve, set **Curve Start (%)** between 0 and 100. **0** follows the curve from the block's beginning, **50** begins at its midpoint, and **100** targets the curve's first point only at the block's last generated sample. At 100 no time remains for traversing the rest of the curve, unless connected following blocks continue it. Before the chosen percentage there is no path constraint. The curve stays in its existing scene position. The model generates the approach to its first point; the addon does not translate the curve or teleport the rig. Leave enough approach time and remaining traversal time for the distance and prompt.

The percentage stays unchanged when a block moves or changes length; the actual start time scales with it. Timing is measured between the block's first and last included scene frames and snaps forward to the 30 Hz model grid, bounded by its last sample. Both the sidebar and the block edit popup expose this field. Earlier preview builds' frame offsets are converted when read. Restart the companion app once when upgrading from an older runtime.

Touching same-model blocks sharing a curve continue that route after the first block's delayed start. A later block with its own delayed start begins a new traversal of the whole curve, with its prefix available for approaching the new start. Its curve does not have to meet the previous endpoint. Regenerating a subset retains its assigned route section. Native pose keys before the curve begins keep their original root placement.

## Timing and placement

Touching, enabled Kimodo blocks assigned to the **same Curve object** share one traversal of that entire curve. The route is divided in proportion to their durations, using the 30 Hz model sample grid. For example, two consecutive 2-second and 3-second blocks use approximately the first 40% and remaining 60% of one route. The second block continues along the curve instead of restarting at its first point. A single block uses the whole curve. A cyclic shared route completes one lap across the entire group. Reversing the spline reverses the route. Keep path length plausible for the prompt and total group duration.

Groups are derived from enabled scene blocks, independently of the current selection. Regenerating only the middle or last block retains its assigned section; unselected neighbors are not submitted or regenerated. A gap, different Curve object, missing curve, different model or a later block's delayed curve start ends the group. Distinct objects sharing the same Curve datablock still count as different routes. Separate groups traverse their own whole curves. Adjacent curves must meet within 5 cm when the next curve starts immediately; a delayed next start allows an unconstrained approach instead. Changing block lengths, curve timing or group membership repartitions the route; regenerate the affected group to update its existing clips.

The curve's scene location, rotation and scale define the route. Sampling converts the evaluated centerline through the SOMA object's transform and its creation-time units to the model's Y-up meters. Bevel, extrusion and curve height do not define character posture or terrain. Height and body pose remain generated or supplied by user pose keys. Shared curves are evaluated at the first block's percentage-derived start time for the whole group, rather than used as an animated Follow Path constraint. Generation freezes these samples, timing and group membership; editing/replacing a pending curve or changing a group neighbor invalidates the old allocation, including edits to unselected neighbors. Existing clips are updated by regenerating their blocks, not by live curve deformation.

If a previous generated clip supplies the start pose and the curve starts immediately, the assigned curve section should start at that clip's endpoint. An immediate section start farther than 25 cm away is rejected to avoid a teleport (the allowance includes ordinary hip sway). Increase Curve Start (%) to generate an approach instead. An explicit user start key still supplies the body pose. While the curve is active, native pose targets retain their posture and height but their horizontal root placement is moved onto the route. Before it begins, keys retain their original root placement. Their source Action, key times and correction layer remain intact. Removing Path Curve makes the original root placement available again.

The external worker submits a dense official `Root2DConstraintSet` at 30 Hz alongside pose constraints. The curve guides the smoothed ground-plane root. Without a starting pose, the curve's initial tangent initializes the heading; subsequent facing is generated, rather than forcibly rotated toward the tangent at every frame. The default Kimodo postprocessor allows 4 cm of pelvis motion around the path to retain body sway. Its final re-encoded smoothed root may differ slightly more, particularly at bends and endpoints. Turning Motion Post-Processing off retains the model's approximate constraint following. Generated clips remain native NLA, with automatic application and the usual user correction layer.

## Verification

Separate Blender 5.2.3 background processes exercised actual scene data and GPU inference; the user's GUI was not automated.

- `results/blender_bridge/curve_start.json` and `curve_start_installed.json`: 0/50/100 percent timing, movement/resizing, shared-route/subset allocation, restarts at a later delay, 24/30/60/fractional FPS, malformed offsets, legacy timing and save/reopen.
- `results/blender_bridge/curve_start_kimodo_generation.json` and `curve_start_ardy_generation.json`: real delayed-route generation, previous-clip history, native NLA application and preservation of a pre-curve authored root key. The tested delayed interval is equivalent to a 40% start on the 150-frame block. Measured inherited start errors were zero; pelvis-to-path deviations peaked near 4 cm.
- `results/blender_bridge/curve_start_ardy_100_generation.json` and `curve_start_kimodo_100_generation.json`: actual 100% endpoint-only conditioning and automatic NLA application, with the previous start pose and pre-curve native key preserved. Final pelvis errors were approximately 1.37 cm and 4.00 cm respectively.
- `results/blender_bridge/shared_curve.json`: unequal three-block allocation, identical partial-regeneration samples, gaps/different objects/disabled neighbors, unselected-neighbor stale detection, 24/60/fractional FPS and save/reopen.
- `results/blender_bridge/shared_curve_generation.json`: actual Kimodo 60/90-frame sequence on one shared route, second-block-only regeneration without restarting, inherited boundary with zero measured root difference, unchanged first clip/source keys and one SOMA/playback track.
- `results/blender_bridge/curve_paths.json`: Bezier/Poly/NURBS, world and rig transforms, centimeter units, original bevel/extrusion preserved, temporary object cleanup, invalid/multi-spline/stale path rejection, popup selection and saved pointer persistence.
- `results/blender_bridge/curve_generation.json`: two joined Bezier blocks generated in one Kimodo sequence, followed by a no-curve block and an inherited curve. Native NLA output matches model root positions at sampled frames, including old root-key frames, without restoring those old positions over the path. User Action/slot/keys and one SOMA/playback track are retained.
- `results/blender_bridge/curve_unkeyed.json`: a curve-only block without user pose keys, offset in the scene, generated at 30 Hz and interpolated on a 60 FPS timeline.

In the two-curve fixture, maximum pelvis deviation from the route was 0.04002 m and maximum final smoothed-root deviation was 0.06636 m. Sampled Blender root differences from model output were below 0.000001 m. These results verify implementation behavior for these fixtures; they do not establish general animation quality or manual UI acceptance.
